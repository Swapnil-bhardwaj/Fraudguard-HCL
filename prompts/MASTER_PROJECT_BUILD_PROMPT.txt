PROJECT GOAL
Build an end-to-end demonstration that analyses credit-card transaction records and flags unusual transactions for human review. Implement and compare Isolation Forest, Local Outlier Factor (LOF), and an Autoencoder where feasible. The application must make clear that a fraud flag is a risk signal, not proof of fraud, and it must not automatically decline a transaction or make a real financial decision.

5. Feature engineering:

   - use log1p/RobustScaler or a justified scaler for skewed `amount`;
   - encode `merchant_category` and `card_type` with preprocessing fitted on train data only;

   - exclude `trans_id` as an identifier/predictor;
   - do not use raw `card_token` as a direct model feature. If card-history/velocity features are attempted, create them using prior transactions only, sort chronologically, and prevent any future/label leakage. Explain this feature decision.
   - never include `is_fraud` in feature matrix `X`; use it only as target for supervised learning and as an evaluation label.
6. Models:
   A. Isolation Forest: train using the features in a reproducible pipeline. Where appropriate fit on predominantly legitimate transactions only; record the contamination/threshold selection strategy. Keep score direction consistent in the model comparison.
   B. Local Outlier Factor: for scoring unseen transactions, use `novelty=True`; train it only on its training data and use prediction/scoring methods only on held-out/new data. Never evaluate novelty scores on the same data used to fit it as if they were held-out results.
   C. Autoencoder: train on legitimate training transactions only where feasible; use reconstruction error as the anomaly score, choose threshold using validation data (or a documented training-based threshold if validation labels are impossible), persist the threshold and architecture. Make TensorFlow optional with a clear UI warning if unavailable.
   D. Supervised comparison: only if the label counts in training are sufficient. Use a simple, explainable baseline such as Logistic Regression or Random Forest with class weights; optionally compare to SMOTE/SMOTENC. Resampling must occur inside the training process/fold only, never before train/test split. With categorical variables, prefer a properly implemented SMOTENC/preprocessing pipeline; do not apply vanilla SMOTE to raw category strings. Dynamically set `k_neighbors <= minority_count - 1`; if fewer than two minority examples are available, skip resampling with a recorded warning instead of crashing.
   E. The three anomaly detectors may not directly use class labels for training. Do not claim that SMOTE improves unsupervised anomaly algorithms. If SMOTE is mandated, use it only for the supervised benchmark and explain its scope.
